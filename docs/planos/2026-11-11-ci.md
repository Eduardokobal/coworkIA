> **Para quem executa:** use a habilidade superpowers:executing-plans, tarefa por tarefa. Os passos usam caixas de seleção (`- [ ]`).

**Objetivo:** criar o workflow do GitHub Actions que roda o lint, os tipos, o build, os testes e as travas em cada PR para a main e em cada push na main, e pôr o selo do CI no README, como a spec do CI descreve (CI1 a CI9 e CI14). - O código, os testes e a demonstração não mudam. Não há mutações. O workflow é conferido pela leitura contra a spec, pelo teste no Docker (CI13) e pela primeira execução no próprio PR, que precisa sair verde antes do merge (CI14).

### Tarefa 1: o workflow (CI1 a CI8)

- [ ] **Passo 1: escrever**

Criar `.github/workflows/ci.yml` com este conteúdo:

```yaml
# Os testes automáticos do coworkIA, descritos em docs/specs/2026-11-11-ci.md.
name: CI

# CI2: só os PRs para a main e os pushes na main. O pull_request_target nunca é usado.
on:
  pull_request:
    branches: [main]
  push:
    branches: [main]

# CI4: o token do workflow só lê o repositório.
permissions:
  contents: read

# CI5: num PR, um push novo cancela a execução anterior; na main, cada push tem um grupo só dele.
concurrency:
  group: ci-${{ github.event_name == 'pull_request' && github.ref || github.sha }}
  cancel-in-progress: true

jobs:
  # CI6: o nome do job é o da checagem que a regra da main exige.
  verificar:
    name: verificar
    runs-on: ubuntu-latest
    timeout-minutes: 15
    steps:
      # CI7 e CI8: as actions do GitHub, presas pelo hash do commit da versão.
      - name: Baixar o código
        uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false
      - name: Instalar o Node 24
        uses: actions/setup-node@949feb2413d6458794dcd2491c4babbbce0c15c1 # v7.1.0
        with:
          node-version: 24
      - name: Instalar as dependências, sem os scripts de instalação
        run: npm ci --ignore-scripts
      - name: Lint
        run: npm run lint
      - name: Tipos
        run: npm run tipos
      - name: Build
        run: npm run build
      - name: Testes
        run: npm test
      - name: Testes das travas
        run: sh testes-travas/rodar.sh
```

Depois de escrever, conferir:

```bash
git status --short
sha256sum .github/workflows/ci.yml
npm run lint
```
Esperado: só o `.github/` novo no status, o sha256 `19be86d548e88280a6b072e36f0044848c0cff3eca090799b8a8fa3360f24dd6` (47 linhas acrescentadas e 0 removidas) e o lint com "No fixes applied".

## Ensaio

O DEV escreveu o `ci.yml` e o selo primeiro numa sonda, um clone no scratchpad saído da main `8eacebc`, com as dependências instaladas por `npm ci --ignore-scripts`, e conferiu o `ci.yml` com a spec, item por item. O lint da sonda passou a ler 82 arquivos, um a mais que antes, porque o Biome também lê o `ci.yml`, e deu "No fixes applied". Um gerador montou este plano a partir da sonda: o `ci.yml` entra inteiro, e a troca do README sai do diff entre a main e a sonda, com a conferência de que aplicar a troca na main dá exatamente o README da sonda.

Depois, o DEV aplicou o plano do zero num clone novo, saído da main `8eacebc`, com as dependências instaladas por `npm ci --ignore-scripts` e as travas ativas. Um script rodou cada linha dos blocos de comando, na ordem, criou o `ci.yml` e fez a troca lida deste arquivo. O Passo 1 da Tarefa 0 foi feito à mão, porque o `origin` do clone é a pasta do projeto, e não o GitHub: a `origin/main` do clone veio da `origin/main` da pasta, que está no `8eacebc`, e o `git fetch origin` desse passo não rodou no clone. Os resultados:
- os 34 comandos saíram com 0. O script criou 1 arquivo e fez 1 troca;
- cada um dos 4 sha256 deu o esperado. O `ci.yml` e o README do fim são iguais, byte a byte, aos da sonda, e a spec commitada é igual à versão 2 (`27f639714e499e1a94f28601ba86e51498cc1897704e221fbef52278fcaa04e0`);
- no fim:
  - 38 arquivos e 496 testes passando, nenhum pulado, como na main;
  - o lint, os tipos e o build com 0, e o `npm run formatar` com "No fixes applied";
  - as travas com 62 casos e 0 falhas;
  - os 4 commits pelas travas, todos com o autor do git global;
  - 4 arquivos no diff, e o status vazio.

Os patch-ids dos 3 commits que não dependem do texto deste plano, na ordem:
- a spec, `36f67813b726d63a0cdbb7921f721d04bd8fb44a`;
