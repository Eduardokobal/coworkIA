- [ ] **Passo 1: escrever o teste**

Criar `testes/versao.test.ts` com este conteúdo:

```ts
import { readFileSync } from 'node:fs';
import { fileURLToPath } from 'node:url';
import { Client } from '@modelcontextprotocol/sdk/client/index.js';
import { InMemoryTransport } from '@modelcontextprotocol/sdk/inMemory.js';
import { describe, expect, it } from 'vitest';
import { carregarDadosDemo } from '../src/fontes/demo/dados.js';
import { criarFontesDemo } from '../src/fontes/demo/fonte-demo.js';
import { criarServidor } from '../src/servidor.js';
import { relogioFixo } from '../src/tempo.js';

const SP = 'America/Sao_Paulo';
const PASTA = fileURLToPath(new URL('../dados-demo', import.meta.url));

function ler(arquivo: string): unknown {
  return JSON.parse(readFileSync(new URL(`../${arquivo}`, import.meta.url), 'utf8'));
}

const pacote = ler('package.json') as { version: string };

describe('a versão do coworkIA (spec da versão 1.0.0, V2)', () => {
  it('o servidor informa ao cliente a versão do package.json', async () => {
    const relogio = relogioFixo('2026-11-04T10:30', SP);
    const servidor = criarServidor({
      fontes: criarFontesDemo(carregarDadosDemo(PASTA, relogio()), SP),
      relogio,
      fuso: SP,
      importantes: [],
    });
    const [doCliente, doServidor] = InMemoryTransport.createLinkedPair();
    await servidor.connect(doServidor);
    const cliente = new Client({ name: 'teste-versao', version: '0.0.0' });
    await cliente.connect(doCliente);
    const informada = cliente.getServerVersion();
    await cliente.close();
    expect(informada).toEqual({ name: 'coworkia', version: pacote.version });
  });

  it('o package-lock.json tem a versão do package.json, na raiz e no pacote ""', () => {
    const lock = ler('package-lock.json') as {
      version: string;
      packages: Record<string, { version?: string }>;
    };
    expect([lock.version, lock.packages['']?.version]).toEqual([pacote.version, pacote.version]);
  });
});
```

## Ensaio

O DEV escreveu e mediu o código numa sonda, um clone no scratchpad saído da main `758dc9e`. O teste veio antes e passou com o 0.1.0 nos três arquivos. Depois, o DEV trocou um arquivo por vez e rodou o teste depois de cada troca: com só o `package.json` em 1.0.0, caíram os 2 casos; com o `package-lock.json` também, caiu só o do servidor; com o `src/servidor.ts`, passaram os 2. Na sonda, o `npm ci --ignore-scripts`, que o CI usa, aceitou o `package-lock.json` com o 1.0.0. Ele também aceitou o `package.json` em 1.0.1 com o lock em 1.0.0, porque confere as dependências, e não a versão do projeto (achado 162). Um gerador montou este plano a partir dela: as trocas saem do diff entre a main e a sonda, e o gerador conferiu que cada trecho "trocar" aparece uma vez e que aplicar as trocas na main dá exatamente o arquivo da sonda.

Depois, o DEV aplicou esta versão do plano do zero num clone novo, saído da main `758dc9e`, com as travas ativas. Um script rodou cada linha dos blocos de comando, na ordem, e fez cada troca e o arquivo novo lidos deste arquivo. O Passo 1 da Tarefa 0 foi feito à mão, porque o `origin` do clone é a pasta do projeto, e não o GitHub: a `origin/main` do clone veio da `origin/main` da pasta, no `758dc9e`, sem o `git fetch origin`. As dependências vieram do `npm ci --ignore-scripts`. Os resultados:
- só os vermelhos dos Passos 4 e 5 da Tarefa 1 saíram com 1, com as mensagens do plano, e os outros 34 comandos saíram com 0. O script criou 1 arquivo e fez 3 trocas;
- o teste passou com o 0.1.0, e o verde do Passo 6 deu os 2 casos e os tipos com 0;
- cada um dos 4 sha256 de arquivo deu o esperado. Os 4 arquivos de código e de teste do fim são iguais, byte a byte, aos da sonda, e a spec commitada é igual à versão 2;
- no fim:
  - 42 arquivos e 528 testes passando, nenhum pulado;
  - o lint, os tipos e o build com 0, e o `npm run formatar` com "No fixes applied";
  - as travas com 62 casos e 0 falhas;
  - os 4 commits pelas travas, todos com o autor do git global;
  - 6 arquivos no diff, e o status vazio.

A versão 1 deste plano passou por um ensaio do mesmo jeito, com os mesmos resultados. O código e o teste do fim dos dois ensaios são iguais, byte a byte.

Os patch-ids dos 3 commits que não dependem do texto deste plano, iguais nos dois ensaios, na ordem:
- a spec, `ad65b5cb642e9a1c83359dc789bbac1ef321d113`;
